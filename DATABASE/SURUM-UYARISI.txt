SURUM UYARISI - DATABASE .bak dosyasi
=====================================

Bu klasordeki yedek dosyasi SQL Server 2025 (surum 17.0.1125.2) ile alinmistir:

  03_SRO_WEB_GAME.bak -> SRO_WEB_GAME (web semasi: seed tablolari dolu,
                                       oyuncu tablolari bos)

NOT: SRO_VT_SHARD ve SRO_VT_ACCOUNT pakete DAHIL DEGILDIR - bunlar vSRO
topluluk standardidir, kendi vSRO veritabani setinizi kullanin ve
DATABASE/QUERY/06_shard_parite.sql dosyasini KENDI shard'iniza uygulayin
(ayrintisi README'de).

ONEMLI: SQL Server bir yedegi YALNIZCA ayni veya daha YENI surumde geri
yukleyebilir. Bu .bak dosyasi SQL Server 2025 (17.x) ve uzeri ister;
2019/2022 gibi eski surumler "The database was backed up on a server
running version 17..." hatasiyla REDDEDER.

Eski surum kullaniyorsaniz ALTERNATIF: DATABASE/QUERY klasorundeki numarali
.sql dosyalariyla web semasini sifirdan kurun (01'den sirayla; README'de).

Geri yukleme ornegi (dosya yollarini kendi kurulumunuza gore degistirin):

  RESTORE DATABASE SRO_WEB_GAME FROM DISK = N'C:\YOL\03_SRO_WEB_GAME.bak'
  WITH MOVE 'SRO_WEB_GAME'     TO N'C:\SQLDATA\SRO_WEB_GAME.mdf',
       MOVE 'SRO_WEB_GAME_LOG' TO N'C:\SQLDATA\SRO_WEB_GAME_log.ldf';

  (Mantiksal ad listesi icin: RESTORE FILELISTONLY FROM DISK = N'...bak')

NOT: SRO_VT_LOG veritabani da pakete DAHIL DEGILDIR (yalniz gunluk
tablolari icerir). config.json'daki "log" alanini mevcut ya da bos bir
veritabanina isaretleyebilirsiniz.
